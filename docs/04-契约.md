# 04 · 契约（v1，冻结）

> 本文件是**唯一的跨模块编译边界**。任何实现都必须按这里的签名/字段/格式来，不得自行改名。
> 违反契约的改动必须同时改本文件和 `schema/*.json`，并升版本号。

---

## 0. 术语

| 术语 | 含义 |
| --- | --- |
| **靶包 canary** | 我们提供的「正常包」。用户对它做任意修补（重打包、注入、hook、脱壳后改）。 |
| **检测内核 core** | `io.litmus.core` 包，纯 Java + 一层 native。可整体拷进任意 Android 应用。 |
| **平面 plane** | `self`（应用自检）/ `device`（设备环境，Momo 那套）/ `cli`（进程外记账）。 |
| **向量 vector** | 一条检测点，有稳定 `id`，是打分的最小单位。 |
| **修补点 patch point** | 靶包里一个「用户会去改」的东西（签名、dex、so、清单属性…），有稳定 `id`。 |
| **信号 signal** | 一个向量在一次运行中的结论。 |
| **事实 fact** | 一个**原始观测值**（不做判定），交给 CLI 平面复核。 |

设计原则：**Probe 只产出「事实 + 结论」，绝不自己写分数**；分数只在 `Score`（App 本地摘要）和 `litmus_score.py`（CLI，权威）里算。

## 1. Java 契约

### 1.1 `io.litmus.core.Signal`

```java
public final class Signal {
    public static final String CLEAN    = "CLEAN";     // 未发现篡改
    public static final String SUSPECT  = "SUSPECT";   // 有痕迹，证据不足
    public static final String TAMPERED = "TAMPERED";  // 确认被改
    public static final String UNKNOWN  = "UNKNOWN";   // 本设备/本版本测不了（不扣分，单独统计）
    public static final String ERROR    = "ERROR";     // 探针自己炸了（不扣分，单独统计）
    public static final String FLAKY    = "FLAKY";     // 多次采样不一致（不扣分，标记「该检测不可靠」）
    // 字段：id, category, verdict, confidence[0,1], weight[1,5], tier("A"|"B"|"C"), evidence, ms
}
```

`evidence` 是**一行给人看的证据**，必须满足：不含用户隐私（不写包名以外的应用列表）、不超过 300 字符、可定位（写清读了哪个文件/哪个 API/哪个偏移）。

### 1.2 `io.litmus.core.Probe`

```java
public interface Probe {
    String id();                                   // 稳定 id，见 §3
    String category();                             // 见 §2，必须与 id 前缀一致
    default int weight() { return 3; }             // 1..5，越大越重要
    default String tier() { return "B"; }          // 证据强度，见 §2.2
    void run(LitmusContext ctx, Probe.Sink sink) throws Exception;

    interface Sink {
        void emit(String verdict, double confidence, String evidence);
        default void clean(String ev)                  { emit(Signal.CLEAN,   0.95, ev); }
        default void suspect(String ev, double conf)   { emit(Signal.SUSPECT, conf, ev); }
        default void tampered(String ev, double conf)  { emit(Signal.TAMPERED,conf, ev); }
        default void unknown(String ev)                { emit(Signal.UNKNOWN, 0.0,  ev); }
        default void error(String ev)                  { emit(Signal.ERROR,   0.0,  ev); }
    }
}
```

**约定**：
- 一个 Probe **只能 emit 一次**（多个结论请拆成多个 Probe）。Runner 会忽略第二次 emit。
- Probe **不得抛异常给 Runner**（Runner 兜底转 ERROR），但可以 `sink.error(...)` 自己上报。
- Probe **不得 sleep 超过 50ms**（`rt.timing` 除外，它自带 200 次采样）。

### 1.3 `io.litmus.core.LitmusContext`

```java
public final class LitmusContext {
    public final android.content.Context app;   // application context
    public final AppSnapshot           appSnap; // 包/进程/签名/哈希快照（Runner 采一次）
    public final NativeSnapshot        nat;     // native 一次性快照；null = 没有 native
    public final Facts                 facts;   // 原始事实袋子，序列化进 report.facts
}
```

## 2. 分类与权重

### 2.1 六个类别（`category` 取值，固定）

| category | 中文 | 默认聚合权重 `a_k` |
| --- | --- | --- |
| `runtime-integrity` | 运行时完整性 | 0.24 |
| `injection` | 注入痕迹 | 0.22 |
| `package-integrity` | 包完整性 | 0.20 |
| `privilege` | 提权面 | 0.14 |
| `virtualization` | 虚拟化/多开/模拟器 | 0.10 |
| `environment` | 环境面 | 0.10 |

`id` 前缀必须与 category 一一对应：`rt.` / `inj.` / `pkg.` / `priv.` / `virt.` / `env.`。

### 2.2 证据强度 `tier`

| tier | 含义 | 默认 confidence | 说明 |
| --- | --- | --- | --- |
| **A** | 不变量/密码学。不依赖「找特征」，改了就一定不成立（内存段哈希、GOT 落点、签名链、APK 内容哈希） | 0.9~1.0 | 这类结论**不允许**在证据不足时下 TAMPERED |
| **B** | 交叉视图。同一事实多路径读取比对（libc vs 裸 syscall、/proc vs Binder、stat vs readdir） | 0.6~0.85 | |
| **C** | 特征匹配。包名/属性/文件/端口/线程名黑名单 | 0.3~0.6 | **只能出 SUSPECT**，出 TAMPERED 必须另有 A/B 佐证 |

> **通吃的关键**：框架适配器（§5）只贡献 tier C 的加分；能不能抓到人靠 tier A/B 的**不变量**。

### 4.3 logcat 协议

- 单行 ≤ 4000 字节：`LitmusReport I LITMUS_REPORT {"schema":…}`（`JSONObject.toString()` 无换行）
- 超长：`LITMUS_REPORT_CHUNK <idx>/<total> <base64>`，CLI 按 idx 拼
- 兜底：`LITMUS_REPORT_PATH /sdcard/Android/data/io.litmus.canary/files/litmus/<runId>.json`

### 4.4 Zip 指纹算法（Java / Python 必须逐字节一致）

```
按 central directory 顺序遍历 entry：
line = f"{name}|{crc32:08x}|{size}|{compressedSize}|{method}\n"
fingerprint = sha256(utf8(concat(lines))).hexdigest()
```
Java 用 `java.util.zip.ZipFile#entries()`，Python 用 `zipfile.ZipFile#infolist()`。

### 4.5 native JSON（`NativeBridge.snapshot()` 返回值）

```jsonc
{
  "ok": true, "abi": "arm64-v8a", "pid": 123, "tracerPid": 0, "vdsoSize": 8192,
  "anonExec":  {"count": 2, "bytes": 65536, "samples": ["7f00..-7fff.. r-xp 00:00"]},
  "rwx":       {"count": 0, "samples": []},
  "memfd":     {"count": 0, "samples": []},
  "deleted":   {"count": 1, "samples": ["/data/app/…/base.apk (deleted)"]},
  "threads":   {"count": 34, "names": ["main", "Signal Catcher"]},
  "inlineHook":{"scanned": 12, "hits": 0, "samples": []},
  "gotCheck":  {"scanned": 0, "bad": 0, "samples": []},
  "timing":    {"n": 200, "medianNs": 31, "p99Ns": 44, "jitterNs": 9}
}
```

任一项失败时该子对象可缺省；`ok=false` 时 `error` 字段给原因。Java 侧**必须能容忍缺字段**。

#### 4.5.1 允许的附加子键（v0.1 实现已产出，Java 可忽略）

契约只保证上面这些键存在；下列是 native 侧**新增的诊断字段**，读不到就按缺省处理，不进判据：

| 位置 | 键 | 含义 |
| --- | --- | --- |
| 顶层 | `elapsedMs` | 本次 `snapshot()` 自身耗时 |
| `memfd` / `deleted` | `so` `dex` `apk` | 样本里含 `.so` / `dex` / `.apk` 的条数 |
| `inlineHook` | `libs` | 真正比对了符号的 `.so` 个数 |
| `inlineHook` | `tramp` | 命中里带经典跳板形态的个数（ARM64 `LDR X16,#8; BR X16` 等） |
| `inlineHook` | `skipped` | 打不开 / inode 不符而跳过的 `.so` 数 |
| `inlineHook` | `truncated` | `1` = 撞时间或数量上限，**结果不完整**（判据必须因此降级为 UNKNOWN，不许当 CLEAN） |
| `gotCheck` | `plt` `nulls` `ms` | `.rela.plt` 条目数 / 值为 0 的弱符号槽 / 耗时 |

**硬约束**：`inlineHook.scanned == 0` 或 `truncated == 1`、`gotCheck.scanned == 0` 时必须出 `UNKNOWN`。
「没测成」与「测了没问题」在报告里必须可区分。

## 5. 框架适配器契约（v0.2 用，v0.1 只留接口）

`docs/05-框架适配矩阵.md` 定义每个框架的「期望痕迹」。适配器只做两件事：

1. `hints()` → 一组 tier C 的弱信号（包名/端口/线程名/属性）。
2. `deploy()` → （仅测试台用）自动布防该框架。

**适配器永远不能把 tier C 提升成 TAMPERED**，这条是硬约束，防止「通吃」退化成「特征匹配大全」。
